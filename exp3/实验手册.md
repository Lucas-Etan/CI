# 实验 03：A* 算法求解八数码问题

## 1. 实验内容、目的与最终应用

### 1.1 先看几个实际例子

当一个问题存在许多可能步骤时，程序不仅要找到答案，还要尽量少走无意义的分支。本实验会实现 A* 搜索，让程序把一个打乱的八数码棋盘恢复到目标状态。

* **A\* 搜索**：同时考虑已经付出的路径代价和对剩余代价的估计，优先探索看起来最有希望状态的搜索算法。

A* 的思想可以用于：

- 拼图求解：输入一个可解的八数码状态，输出最短动作序列和每一步棋盘。
- 地图寻路：道路长度是已经走过和将要走的代价，直线距离可以提示目标方向。
- 游戏角色移动：在网格地图中绕开障碍，寻找代价较低的路线。
- 机器人任务规划：在多个动作组合中寻找从当前状态到目标状态的可行序列。
- 网络路由：在候选路径中综合已知链路代价和目标方向进行选择。

八数码由 1～8 和一个空格组成，移动空格就会产生新状态。

* **状态**：某一时刻描述问题所需的完整信息；本实验用长度为 9 的元组表示棋盘，数字 0 代表空格。

所有可由移动产生的棋盘和它们之间的联系构成状态空间。

* **状态空间**：问题全部可能状态及状态转换关系组成的集合；搜索算法在其中寻找从起点到目标的路径。

### 1.2 实验内容

我们会在已经创建好的骨架中依次完成：

1. 检查棋盘是否由 0～8 各一次组成。
2. 用逆序数奇偶性提前拒绝无解状态。
3. 生成空格向上、下、左、右移动后的合法后继。
4. 计算非零数字到目标位置的曼哈顿距离。
5. 用 `heapq` 实现 A* 优先队列、最短已知代价和父节点记录。
6. 回溯得到最短动作序列，并与没有启发信息的统一代价搜索比较。
7. 保存 JSON 与逐步棋盘文本，并在最终输出中显示本人学号。

* **后继**：从当前状态执行一个合法动作后直接到达的新状态。

* **启发信息**：根据问题结构估计一个状态离目标还有多远的信息；它帮助搜索决定先探索哪个方向。

### 1.3 实验目的

完成实验后，我们应能：

- 区分路径代价 `g(n)`、启发估计 `h(n)` 和综合代价 `f(n)`。
- 解释曼哈顿距离为什么适合八数码。
- 使用最小堆维护待探索状态。
- 说明为什么需要保存每个状态的最短已知代价和父节点。
- 用扩展节点数比较有启发搜索与无启发搜索的效率。
- 对无解输入给出明确错误，而不是无限搜索。

* **路径代价 g(n)**：从起点到当前状态已经执行的动作数，本实验每次移动代价为 1。

* **启发估计 h(n)**：从当前状态到目标状态剩余代价的估计值，本实验使用曼哈顿距离。

* **综合代价 f(n)**：A* 的排序依据，计算为 `f(n)=g(n)+h(n)`。

## 2. 问题拆解与文件关系

### 2.1 状态、动作和目标

默认起点和目标分别是：

```text
起点          目标
1 3 6         1 2 3
5 _ 2         4 5 6
4 7 8         7 8 _
```

下划线表示空格 0。程序中棋盘使用元组而不是列表。

* **元组**：创建后不能原地修改的有序序列；八数码状态用元组后可以安全地作为字典键。

* **字典键**：用于在字典中定位值的对象；键需要保持稳定并可哈希，因此可变列表不能直接作为键。

### 2.2 A* 每次选择什么

A* 把尚待探索的状态放入 frontier，并优先弹出 `f` 最小的状态。

* **frontier**：已经发现但尚未展开的候选状态集合，也常称开放表。

* **展开节点**：从 frontier 取出一个状态，生成并检查它的所有合法后继；扩展数量可以反映搜索工作量。

本实验用最小堆实现 frontier。

* **最小堆**：一种能快速取出最小元素的数据结构；Python 的 `heapq` 根据元组从左到右比较字段。

### 4.2 FILL-02：统计逆序数

把空格 0 去掉后，如果前面的数字大于后面的数字，这一对就构成逆序对。

* **逆序对**：序列中位置在前但数值更大的两个元素；逆序对总数的奇偶性用于判断八数码的可达性。

对于 3×3 八数码，起点与目标的逆序数奇偶性相同才有解。

* **奇偶性**：整数是奇数还是偶数的性质；合法移动不会改变 3×3 八数码相对于目标的可解奇偶类别。

**理论说明：** 先过滤空格，再枚举所有 `i<j` 的位置组合。Python 中布尔值可在求和时当作 1 或 0，因此判断表达式可以直接交给 `sum`。

将 FILL-02 替换为：

```python
values = [value for value in board if value != 0]
return sum(
    values[i] > values[j]
    for i in range(len(values))
    for j in range(i + 1, len(values))
)
```

**实践方式：** 检查目标状态和交换 7、8 后的状态：

```powershell

```

**运行验证：** 应依次输出：

```text

1
False
```

**QA：** 如果第二个逆序数不是 1，确认 `values` 已排除 0，并且内层索引从 `i+1` 开始。

## 5. 启发函数与后继生成

### 5.1 FILL-03：曼哈顿距离

一个数字当前位置和目标位置的行差绝对值加列差绝对值，就是它的曼哈顿距离。

* **曼哈顿距离**：网格中只允许横向、纵向移动时，两点的行坐标差绝对值与列坐标差绝对值之和。

该估计不会把空格计入，也不会高估剩余最少移动数。

* **可采纳启发函数**：对任一状态都不高估真实剩余最小代价的启发函数；使用它的 A* 可以保持最优性。

**理论说明：** 先为目标中的每个数字建立坐标索引，再遍历当前棋盘。`divmod(index, 3)` 一次得到行和列，空格 0 直接跳过。

将 FILL-03 替换为：

```python
goal_positions = {
    value: divmod(index, SIZE)
    for index, value in enumerate(goal)
}
distance = 0
for index, value in enumerate(board):
    if value == 0:
        continue
    row, column = divmod(index, SIZE)
    goal_row, goal_column = goal_positions[value]
    distance += abs(row - goal_row) + abs(column - goal_column)
return distance
```

**实践方式：** 目标状态的距离应为 0，一个数字只差一步时距离应为 1：

```powershell
python -c "from puzzle import GOAL, manhattan; print(manhattan(GOAL)); print(manhattan((1,2,3,4,5,6,7,0,8)))"
```

**运行验证：** 应输出：

```text
0
1
```

**QA：** 如果目标状态不是 0，检查是否错误地把空格 0 也加入距离。

### 5.2 FILL-04：生成合法后继

空格在中心时有四种移动，在边缘时有三种，在角落时有两种。生成器可以逐个产出后继，无需先保存完整列表。

* **生成器**：使用 `yield` 按需产生值的函数；调用方可以逐个遍历结果，减少不必要的中间列表。

**理论说明：** 找到空格的一维索引后转成行列坐标。对四个方向计算新坐标，越界就跳过；合法时复制为列表、交换两个位置，再转回元组输出。

将 FILL-04 替换为：

```python
blank = board.index(0)
row, column = divmod(blank, SIZE)
for move, delta_row, delta_column in MOVES:
    next_row = row + delta_row
    next_column = column + delta_column
    if not (0 <= next_row < SIZE and 0 <= next_column < SIZE):
        continue

    target = next_row * SIZE + next_column
    values = list(board)
    values[blank], values[target] = values[target], values[blank]
    yield move, tuple(values)
```

**实践方式：** 用空格居中的棋盘检查四个后继：

```powershell
python -c "from puzzle import neighbors; items=list(neighbors((1,2,3,4,0,5,6,7,8))); print(len(items)); print([move for move, _ in items])"
```

**运行验证：** 应输出：

```text
4
['UP', 'DOWN', 'LEFT', 'RIGHT']
```

**QA：** 如果原棋盘被修改，说明直接在元组或共用列表上交换了位置。每个后继都应执行一次 `values = list(board)`。

## 6. 实现 A* 主循环

### 6.1 FILL-05：初始化搜索记录

堆元素按 `(f, h, 序号, g, 状态)` 保存。`f` 相同时优先选择 `h` 较小者；再相同时使用递增序号，避免让 Python 比较棋盘状态来决定顺序。

* **平局处理**：多个候选排序关键值相同时使用额外字段稳定决定先后；它不改变路径代价，但会影响扩展顺序。

`g_score` 保存每个状态当前发现的最短起点代价，`came_from` 保存父状态和动作。

* **父节点记录**：为每个已改善状态保存“从哪个状态通过什么动作到达”，命中目标后可据此回溯完整路径。

**理论说明：** 起点 `g=0`，所以起点 `f=h`。`itertools.count()` 提供不重复序号。字典初始化后，搜索循环可以随时判断新路径是否更短。

将 FILL-05 替换为：

```python
frontier: list[tuple[int, int, int, int, Board]] = [
    (start_h, start_h, next(counter), 0, start)
]
g_score = {start: 0}
came_from: dict[Board, tuple[Board, str]] = {}
```

### 6.2 FILL-06：弹出候选并检查目标

同一状态可能以不同代价多次进入堆。字典中只保留最好代价，因此弹出时需要比较条目里的 `g` 与当前 `g_score`。

* **过期堆条目**：状态入堆后又发现更短路径时，旧条目仍在堆中；弹出后发现其代价不是最新值，就应跳过。

**理论说明：** `heapq.heappop` 取出 `f` 最小条目。过期条目用 `continue` 丢弃；当前状态等于目标时调用回溯，并把计数一起包装为结果。

将 FILL-06 替换为：

```python
_f, _h, _order, current_g, current = heapq.heappop(frontier)
if current_g != g_score.get(current):
    continue

if current == goal:
    boards, moves = reconstruct_path(came_from, current)
    return SearchResult(
        boards,
        moves,
        current_g,
        SearchStats(expanded, generated, frontier_peak),
    )
```

### 6.3 FILL-07：改善后继路径

如果从当前状态到后继的新代价比已知代价更小，就更新记录；这个过程常称为松弛。

* **松弛**：发现到某个状态的更短路径时，用新代价和新父节点替换旧记录的操作。

**理论说明：** 未见过的状态用无穷大作旧代价。只有新路径更短才更新 `g_score` 和 `came_from`，计算 `h` 后将新的五元组压入堆，并增加生成计数。

将 FILL-07 替换为：

```python
if tentative_g >= g_score.get(next_board, float("inf")):
    continue

g_score[next_board] = tentative_g
came_from[next_board] = (current, move)
next_h = heuristic(next_board, goal)
heapq.heappush(
    frontier,
    (
        tentative_g + next_h,
        next_h,
        next(counter),
        tentative_g,
        next_board,
    ),
)
generated += 1
```

### 6.4 FILL-08：回溯路径

回溯从目标沿父节点走向起点，天然得到逆序路径，因此最后要整体翻转。

* **路径回溯**：从目标状态沿父节点记录反向追踪到起点，再反转为正向动作序列的过程。

**理论说明：** 只要当前状态存在父记录，就取出父状态和导致当前状态的动作，分别加入列表。循环结束后，棋盘列表包含起点和目标，动作列表比棋盘列表少一个元素。

将 FILL-08 替换为：

```python
while current in came_from:
    current, move = came_from[current]
    boards.append(current)
    moves.append(move)

boards.reverse()
moves.reverse()
return tuple(boards), tuple(moves)
```

### 7.2 为什么还要运行统一代价搜索

主程序把启发函数替换为恒定的 0，再运行同一套搜索代码，此时 `f=g`，算法退化为统一代价搜索。

* **统一代价搜索**：总是扩展当前路径代价最小的状态；当每步代价相同，它与按层搜索相近，但不利用目标方向信息。

对照使用相同起点、目标和后继顺序，因此扩展节点差异主要来自曼哈顿启发信息。

## 11. 综合 QA

### Q1：为什么有一半左右的随机棋盘无解？

3×3 八数码状态被逆序数奇偶性分成两个互不连通的集合，目标只能到达与它奇偶性相同的状态。

### Q2：为什么曼哈顿距离能保持最短路径？

一个数字每次最多向目标位置靠近一格，因此所有数字曼哈顿距离之和不会高估实际剩余动作数。该启发函数在本问题中还满足一致性。

* **一致性**：任一状态的启发估计不大于一步代价加后继的启发估计；一致启发函数使 A* 的代价记录更稳定。

### Q3：为何不使用普通列表保存 frontier 后每次排序？

列表排序能得到正确结果，但每次加入新状态后重新排序成本更高。最小堆专门支持高效插入和取最小元素。

### Q4：内存快速增长怎么办？

先确认输入可解、曼哈顿距离正确、过期条目能够跳过。不要直接尝试非常困难的随机状态；本实验验收以默认案例为基线。

### Q5：动作名称是数字移动方向还是空格移动方向？

本实验统一表示空格移动方向。例如 `RIGHT` 表示空格与右侧数字交换。报告中应沿用这个定义。
